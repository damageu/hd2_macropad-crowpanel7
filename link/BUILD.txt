HD2 Macropad Link v1.2.7
========================

Windows tray app and first-install program for the CrowPanel Advance 7.0
USB-serial link. The updater core is v1.2.3 (flasher stub, compressed writes,
MD5 verify, ROM fallback, headless CLI). v1.2.6 is the published installer
for firmware v1.9.1-cp7.2. v1.2.7 is that program with the bundled app
replaced by v1.9.2-cp7.2. Protocol UART rate: 115200. The updater's bootloader
baud is at most 460800 (never 921600: it corrupts on the CrowPanel's CH340K).
Those are different settings.

The updater does not replace this exe. A future Link update is a new build
of these sources, installed by hand. It does not download or run a new exe.

Build (llvm-mingw or MinGW-w64, from this directory; build.sh does all of it):

    x86_64-w64-mingw32-windres res.rc -O coff -o res.o
    x86_64-w64-mingw32-gcc -Wall -Wextra -O2 ^
      -DMINIZ_NO_STDIO -DMINIZ_NO_ARCHIVE_APIS -DMINIZ_NO_TIME -DMINIZ_NO_ZLIB_COMPATIBLE_NAMES ^
      -c third_party\miniz\miniz.c -o miniz.o
    x86_64-w64-mingw32-gcc -Wall -Wextra -Werror -O2 ^
      -DMINIZ_NO_STDIO -DMINIZ_NO_ARCHIVE_APIS -DMINIZ_NO_TIME -DMINIZ_NO_ZLIB_COMPATIBLE_NAMES ^
      -municode -mwindows ^
      hd2link.c updater_win.c install_win.c romflash.c update_core.c sha256.c md5.c backup_io.c miniz.o res.o ^
      -o HD2MacropadLink-v1.2.7.exe -lsetupapi -lwinmm -lwinhttp -lcomdlg32 -lshell32 -static

Wire-format cross-check against esptool (needs esptool 5.2.0 in a venv):

    python3 -m venv /tmp/etvenv && /tmp/etvenv/bin/pip install esptool==5.2.0
    /tmp/etvenv/bin/python wire_crosscheck.py
    # Runs test_romflash with HD2_WIRE_DUMP, then rebuilds every stub-path packet
    # (MEM_BEGIN/DATA/END, CHANGE_BAUD, SPI_SET, READ_FLASH + acks, SPI_FLASH_MD5,
    # FLASH_DEFL_BEGIN/DATA/END) with esptool's own ESP32S3ROM / ESP32S3StubLoader
    # code and requires byte-identical frames.

Regenerating the stub header (only when moving to a newer stub release):

    python3 gen_stub.py third_party/esp-flasher-stub/esp32s3.json > stub_esp32s3.h

The Windows program in this tree is HD2MacropadLink-v1.2.7.exe. The resource
version is 1.2.7. Link pacing is unchanged: 30 ms hold, 8 ms gap. Flash baud is still
at most 460800.

v1.2.3 updater (fast path):
- Connects exactly as v1.2.2 (ClassicReset, SYNC retries, drains the 7 extra
  SYNC replies), then uploads the ESP32-S3 flasher stub (esp-flasher-stub
  v0.2.0, MIT/Apache) with MEM_BEGIN/MEM_DATA/MEM_END, waits for "OHAI", and
  switches to 460800 with CHANGE_BAUD(new, old).
- Backup: board MD5 (SPI_FLASH_MD5) of the installed app first. If it equals
  the package (reinstall) or a file in backups\ (earlier backup or the
  installed-<ver>.bin copy kept after every verified install), the backup is
  taken from that file, checked by MD5. Otherwise a full READ_FLASH with acks,
  checked by the stub's MD5 digest and SPI_FLASH_MD5. The backup .bin + .sha256
  is always written before anything is erased.
- Write: zlib-compressed FLASH_DEFL_BEGIN/DATA/END to 0x10000 only (app
  region; NVS and presets untouched).
- Verify: SPI_FLASH_MD5 of 0x10000 over the image length (no full readback),
  then the post-reset version confirmation as before.
- Rollback with the backup on any write/verify failure.
- If the stub cannot be loaded (no OHAI, upload rejected, baud rejected, or a
  stub I/O failure before anything was written) the updater logs FALLBACK and
  reruns the whole v1.2.2 ROM-only path automatically.
- Progress per phase (Backup / Write / Verify) in the UI; the log has phase
  durations and throughput and summaries every ~64 KB instead of per packet.

Registry switches (HKCU\Software\HD2MacropadLink, REG_DWORD, default 0):
    FullBackup=1  always read the full app from the board for the backup
    RomOnly=1     skip the stub; use the v1.2.2 ROM-only path
    Log=1         diagnostic link.log (unchanged)

Headless CLI (no dialogs):
    HD2MacropadLink-v1.2.7.exe --update <crowpanel-update.json> --port COM5 [--reinstall] --yes
        [--log-stdout] [--full-backup] [--rom-only] [--dry-run] [--result-file <path>]
    HD2MacropadLink-v1.2.7.exe --probe --port COM5 [--log-stdout] [--rom-only] [--result-file <path>]
    HD2MacropadLink-v1.2.7.exe --install [--port COMn] --yes
        [--dry-run] [--log-stdout] [--rom-only] [--result-file <path>]
Exit codes: 0 ok, 1 failed, 2 usage, 3 port busy or Link running, 4 bad package.

--install is the stock-board first install. It reads 16 MB from address 0
before it writes the bootloader (0x0), the partition table (0x8000), the
app (0x10000), and the assets FAT (0xA10000, 4 MB, compressed). It does not
mass-erase and it does not write NVS. Omit --port when exactly one CH340 is
plugged in. --yes is required to write. --dry-run only saves the 16 MB backup.
Quit the tray app first. The 16 MB backup plus the sound write takes several
minutes. Do not run --install on a board that already runs HD2.

Do not replace the app bin or the assets image with a later rebuild.
v1.2.4 is the previous exe and does not contain the sound partition.

Each update writes a timestamped protocol log under
%LOCALAPPDATA%\HD2MacropadLink\logs\update-<timestamp>.log.
Firmware backups are written under %LOCALAPPDATA%\HD2MacropadLink\backups\.
Startup update check, Install now / Later / Skip, and the manual "Check for
firmware update..." are unchanged from v1.2.2.
